CPU Scheduler Lab

Cómo funcionan los algoritmos de planificación y cómo el programa genera el diagrama de ejecución.

Angular 21 · TypeScript · Python · Streamlit

1. Objetivo del proyecto

CPU Scheduler Lab es un simulador educativo de planificación de procesos. Permite ingresar procesos, seleccionar un algoritmo y observar qué proceso ocupa la CPU en cada unidad de tiempo.

Idea principal: el algoritmo toma decisiones, el timeline guarda esas decisiones y la interfaz convierte el timeline en un diagrama visual.

2. Arquitectura

El proyecto tiene una versión original en Angular y una versión equivalente en Python con Streamlit para el despliegue web. En ambas versiones la lógica se divide en motor de planificación e interfaz.

3. Modelo de datos

Cada proceso tiene un identificador, un tiempo de llegada y un tiempo de CPU:

@dataclass(frozen=True)
class ProcessInput:
    id: str
    arrival: int
    burst: int

Durante la ejecución, el programa mantiene el tiempo restante, el proceso que está utilizando la CPU y el timeline.

remaining = {process.id: process.burst for process in ordered}
timeline = []
steps = []

4. Flujo de una simulación

  1. El usuario edita los procesos y selecciona un algoritmo.
  2. La interfaz valida identificadores, llegadas, tiempos de CPU y quantum.
  3. La función simulate envía los datos al algoritmo correspondiente.
  4. El motor avanza una unidad de tiempo por cada iteración.
  5. En cada iteración se selecciona un proceso y se descuenta una unidad de CPU.
  6. El estado se guarda en timeline y steps.
  7. La interfaz utiliza esos datos para dibujar el diagrama y calcular las métricas.
def simulate(processes, algorithm, quantum=1):
    if algorithm == "srr":
        return simulate_selfish(processes)
    return simulate_standard(processes, algorithm, quantum)

5. Algoritmos implementados

NO EXPROPIATIVO

FCFS - First Come, First Served

Selecciona el proceso disponible que llegó primero. Cuando comienza, continúa hasta terminar.

if algorithm == "fcfs":
    running = available[0].id
    non_preemptive = running
NO EXPROPIATIVO

SJF - Shortest Job First

Selecciona el proceso disponible con menor duración total de CPU. Tampoco interrumpe el proceso actual.

running = min(
    available,
    key=lambda process: (process.burst, process.arrival)
).id
EXPROPIATIVO

SRTF - Shortest Remaining Time First

Revisa en cada unidad cuál proceso tiene menor tiempo restante. Si llega un proceso más corto, puede interrumpir al proceso actual.

running = min(
    available,
    key=lambda process: (
        remaining[process.id],
        process.arrival
    )
).id
COLA CIRCULAR

Round Robin

Reparte la CPU utilizando un quantum. Cuando el proceso consume el quantum y no termina, vuelve al final de la cola.

queue.extend(arrivals)

if running and quantum_used >= quantum:
    queue.append(running)
    running = None

if running is None and queue:
    running = queue.pop(0)
PRIORIDADES DINÁMICAS

Selfish Round Robin

Mantiene grupos de procesos aceptados y nuevos. Los aceptados aumentan su prioridad en uno y los nuevos en dos. Cada turno utiliza una unidad de CPU.

for process_id in accepted:
    priorities[process_id] += 1

for process_id in newcomers:
    priorities[process_id] += 2

6. Cómo se genera el diagrama

El motor agrega el proceso seleccionado al timeline antes de consumir una unidad:

timeline.append(running)

if running:
    remaining[running] -= 1

steps.append(step)
time += 1

Si la CPU no tiene ningún proceso disponible, se guarda None. Por eso el diagrama también puede representar períodos de CPU ociosa.

Representación del timeline

CCACCDDDFEEFGFFBBBBB

Angular recorre cada proceso y cada instante para construir las celdas:

@for (process of processes(); track process.id) {
  @for (time of timeSlots(); track time) {
    <div class="time-cell"
      [class.running]="visibleProcessAt(time) === process.id"
      [style.background]="processColor(index)">
    </div>
  }
}

La función visibleProcessAt oculta las unidades futuras cuando se utiliza el modo paso a paso.

protected visibleProcessAt(time: number) {
  const timeline = this.result()?.timeline ?? [];
  return this.isStepping() && time > this.activeStep()
    ? null
    : timeline[time] ?? null;
}

7. Métricas

El sistema busca la última posición donde aparece cada proceso en el timeline y calcula:

finish = last_position + 1
turnaround = finish - arrival
waiting = turnaround - burst
normalized = turnaround / burst
MétricaSignificado
T FinalInstante en que termina el proceso.
T RetornoTiempo desde la llegada hasta la finalización.
T EsperaTiempo en que el proceso espera CPU.
T PromedioRetorno dividido entre el tiempo de CPU.

9. Guion oral

“CPU Scheduler Lab es un simulador de planificación de procesos. El usuario introduce procesos y selecciona un algoritmo. El programa valida los datos y ejecuta una simulación unidad por unidad. En cada instante se selecciona un proceso, se descuenta una unidad de CPU y se guarda la decisión en un timeline. Después, la interfaz recorre ese timeline para construir una fila por proceso y una fila general de CPU. Finalmente calcula los tiempos de finalización, retorno y espera.”

Para comparar algoritmos, se puede explicar que FCFS y SJF son no expropiativos, SRTF es expropiativo, Round Robin utiliza una cola con quantum y Selfish Round Robin utiliza prioridades dinámicas.
